Run ChangaLab on Codespaces
GitHub Codespaces + ChangaLab

This guide explains how to run ChangaLab inside a GitHub Codespace. A Codespace is a cloud development environment that runs behind the GitHub proxy at https://<codespace-name>-8080.app.github.dev/. Because the proxy hides the real hostname, a few adjustments are required so the site (and its CSS/JS assets) load correctly from your browser.

The repository already contains everything needed for a one-click experience:

  • .devcontainer/devcontainer.json & .devcontainer/setup.sh — install nginx, PHP-FPM and MariaDB, apply the nginx config, create the database and fix storage permissions automatically.

  • changalab.nginx — the reference nginx site config (with absolute_redirect off;).

  • Files/index.php & Files/core/app/Http/Middleware/TrustProxies.php — make Laravel trust the proxy and generate public asset URLs instead of localhost:8080.

  • scripts/backup.sh — database backup & restore utility.

If you prefer to set things up by hand, the manual setup section walks through every command.
Create the Codespace
Spin up a cloud environment from the repo

You can create a Codespace from the repository page or from your terminal.

Option A — GitHub UI

  • Go to the repository and click Code → Codespaces → Create codespace on main.

  • Wait a minute or two while the container image builds and setup.sh installs the services.

Option B — GitHub CLI
gh codespace create --repo fmappcoding/changalab --branch main
Open a terminal inside the Codespace
gh codespace ssh --codespace <CODESPACE_NAME>

The Codespace name looks like laughing-yodel-g4r75gx69x5whv4p7.

Automatic Setup
Everything configured on first launch

With the bundled .devcontainer, no manual commands are required. When the Codespace is created, setup.sh runs automatically and:

  • Installs nginx + PHP 8.3-FPM + MariaDB.

  • Runs composer install in Files/core.

  • Copies changalab.nginx to /etc/nginx/sites-available/changalab and enables it.

  • Starts the services and creates the changalab database + user (changalab / changalab123).

  • Fixes storage permissions to 0775.

If the script did not run (e.g. you attached the repo to an existing Codespace), trigger it manually: 

gh codespace ssh --codespace <CODESPACE_NAME> -- "bash /workspaces/changalab/.devcontainer/setup.sh"

Once it finishes, simply open the forwarded 8080 port in your browser and continue to Run the Installer.

Manual Setup
Step-by-step commands (if not using devcontainer)
1. Install services
sudo apt-get update
sudo apt-get install -y nginx php8.3-fpm php8.3-mysql php8.3-mbstring \
  php8.3-xml php8.3-curl php8.3-zip php8.3-gd php8.3-bcmath mariadb-server
sudo service nginx start
sudo service php8.3-fpm start
sudo service mysql start
2. Apply the nginx config
sudo cp changalab.nginx /etc/nginx/sites-available/changalab
sudo ln -sf /etc/nginx/sites-available/changalab /etc/nginx/sites-enabled/changalab
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo nginx -s reload

Important: the config uses server_name $host; and absolute_redirect off; so nginx never redirects you to http://localhost:8080.

3. Create the database
sudo mysql -e "CREATE DATABASE changalab CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
sudo mysql -e "CREATE USER IF NOT EXISTS 'changalab'@'localhost' IDENTIFIED BY 'changalab123';"
sudo mysql -e "GRANT ALL PRIVILEGES ON changalab.* TO 'changalab'@'localhost';"
sudo mysql -e "FLUSH PRIVILEGES;"
4. Fix storage permissions
cd /workspaces/changalab/Files
sudo chown -R $(whoami):www-data core/storage core/bootstrap/cache
mkdir -p core/storage/app/public
chmod -R 0775 core/storage core/bootstrap/cache
Run the Installer
Finish setup from the browser

Open the forwarded port 8080 in your browser, then go to /install: 

https://<CODESPACE_NAME>-8080.app.github.dev/install

Database details

  • Database Host: 127.0.0.1
  • Database Port: 3306
  • Database Name: changalab
  • Database User: changalab
  • Database Password: changalab123

Important: the database must be empty before import. If you see "Problem Occurred When Importing Database!", reset it: 

sudo mysql changalab -e "DROP DATABASE changalab; CREATE DATABASE changalab CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
Fix CSS / JS (localhost issue)
Why the site looked unstyled and how it's solved

Behind the Codespace proxy, Laravel generated asset URLs like http://localhost:8080/assets/.... Those are unreachable from your browser, so the site appeared with no styling ("a disaster").

This is already fixed in the repository:

  • Files/index.php reads the X-Forwarded-Host / X-Forwarded-Proto headers and overrides $_SERVER['HTTP_HOST'] before Laravel boots, so every asset() uses the public app.github.dev URL.

  • Files/core/app/Http/Middleware/TrustProxies.php (registered in bootstrap/app.php) tells Laravel to trust the proxy headers as defense-in-depth.

If you ever change proxy behaviour, clear the cache after editing: 

cd /workspaces/changalab/Files/core && php artisan optimize:clear
sudo service php8.3-fpm restart
Backup & Restore
Protect your data if the Codespace is deleted

Stopping a Codespace keeps the disk (and database). Deleting it destroys everything. Use scripts/backup.sh to take a portable dump you can restore later.

Inside the Codespace
cd /workspaces/changalab
bash scripts/backup.sh backup     # timestamped .sql.gz in backups/
bash scripts/backup.sh list       # show existing dumps
bash scripts/backup.sh restore backups/changalab-YYYYMMDD-HHMMSS.sql.gz
Pull the dump to your machine
CODE=<CODESPACE_NAME>
gh codespace ssh --codespace $CODE -- "bash /workspaces/changalab/scripts/backup.sh backup"
gh codespace cp $CODE:/workspaces/changalab/backups/<file>.sql.gz ./backups/
FAQ
Common Codespace questions

Do I need to reinstall after stopping the Codespace?

No. Stopping only pauses it; the disk and database are preserved. Just restart the services (mysql, php8.3-fpm, nginx) and open the URL.

What if the Codespace is deleted?

Recreate it from main; the devcontainer sets up services automatically. Then restore your database dump from scripts/backup.sh.

The page redirects to localhost:8080.

Your nginx config is missing absolute_redirect off;. Re-apply changalab.nginx and reload nginx.

Styles don't load (unstyled page).

That's the proxy/asset issue — already fixed in the repo. Make sure you're on the latest main and clear the cache.
